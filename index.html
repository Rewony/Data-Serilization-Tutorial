FORMAT 01

JSON (JavaScript Object Notation) Konu Anlatımı

Modern webin, REST API'lerinin ve NoSQL veritabanlarının evrensel veri taşıma dili

1. JSON Nedir ve Neden XML'in Yerini Aldı?

JSON, 2000'li yılların başında Douglas Crockford tarafından popülerleştirilmiş, hafif (lightweight) ve metin tabanlı bir veri değişim formatıdır. İsmi JavaScript'ten gelse de tamamen dilden bağımsızdır (Python, Java, C#, Go, PHP gibi tüm dillerde yerel olarak desteklenir).

🚀 Hafif ve Hızlı: XML'deki gibi açılış ve kapanış etiketleri tekrarlanmaz, dosya boyutu çok daha küçüktür ve ağ üzerinden hızlı aktarılır.
⚡ Kolay Ayrıştırma: JavaScript içinde JSON.parse() ile tek satırda bellek nesnesine dönüştürülür. Karmaşık DOM tarayıcıları gerektirmez.
🌐 Standart Kullanım: Günümüzde RESTful API'lerin %95'i veri alışverişinde JSON formatını kullanır.

2. JSON'da Geçerli Olan 6 Temel Veri Tipi

JSON çok katı bir spesifikasyona sahiptir. Yalnızca aşağıdaki 6 veri tipini tanır. Bunların dışındaki hiçbir tip (fonksiyonlar, undefined, regex vb.) bulunamaz:

1. String (Metin) "Ahmet Yılmaz" Mutlaka ÇİFT TIRNAK içinde yazılır.
2. Number (Sayı) 42 veya 19.99 Tamsayı veya ondalıklı sayı olabilir.
3. Boolean (Mantıksal) true veya false Küçük harfle yazılır (True/False yanlıştır).
4. Null (Boşluk) null Değerin olmadığını belirtir.
5. Object (Nesne) { "rol": "admin" } Süslü parantez içinde anahtar-değer ikilileri.
6. Array (Dizi / Liste) [ "elma", "armut" ] Köşeli parantez içinde sıralı öğeler.

3. Kritik JSON Sözdizim Kuralları & Sık Yapılan Hatalar

Kural A: Çift Tırnak Şartı (Tek Tırnak Geçersizdir!)

❌ YANLIŞ
{ 'kullanici': 'ahmet', age: 25 }

Tek tırnaklar (') veya tırnaksız nesne anahtarları (age) kesinlikle GEÇERSİZDİR.

✅ DOĞRU
{ "kullanici": "ahmet", "age": 25 }

Tüm anahtarlar ve tüm metin değerler çift tırnak (") içine alınmalıdır.

Kural B: Sonda Fazla Virgül (Trailing Comma) Yasağı

❌ YANLIŞ
[ "elma", "armut", "muz", ]

JavaScript tolerans gösterse bile standart JSON'da son elemandan sonra virgül koyulamaz.

✅ DOĞRU
[ "elma", "armut", "muz" ]

Virgül yalnızca elemanların arasına konulur; en sondaki öğeden sonra virgül bırakılmaz.

Kural C: Yorum Satırları Desteklenmez

JSON saf veri taşıma amacıyla tasarlandığından yorum satırlarına (// yorum veya /* yorum */) izin vermez. Yorum satırı eklerseniz tüm JSON ayrıştırıcıları hata verir.

4. Kusursuz Bir JSON Örneği 

{
  "kullanici_id": 1042,
  "ad": "Zeynep Kaya",
  "aktif": true,
  "roller": ["muhendis", "admin"],
  "iletisim": {
    "email": "zeynep@example.com",
    "telefon": null
  }
}
FORMAT 02

YAML (YAML Ain't Markup Language) Konu Anlatımı

DevOps, Docker, Kubernetes, Ansible ve CI/CD otomasyonunun vazgeçilmez konfigürasyon dili

1. YAML Nedir ve Neden Tercih Edilir?

YAML, insan gözü için maksimum okunabilirlik sağlamak amacıyla tasarlanmış bir veri serileştirme standardıdır. Parantez veya etiket kalabalığı yerine sadece boşluklara (indentation) dayalı bir hiyerarşi kurar.

👁️ Temiz ve Ferah: Süslü parantez ({}), tırnak işaretleri ve virgüller zorunlu değildir. Kod son derece sade görünür.
💬 Yorum Satırları Var: JSON'ın aksine # işareti ile istediğiniz yere açıklama satırları ekleyebilirsiniz.
🐳 DevOps Standartı: Kubernetes pod tanımları, Docker Compose, GitHub Actions iş akışları tamamen YAML ile yazılır.

2. YAML'ın En Katı Kuralı: TAB TUŞU KESİNLİKLE YASAKTIR!

YAML spesifikasyonunda TAB karakteri (\t) sözdizim hatasıdır. Girintileme (indentation) yaparken klavyedeki TAB tuşuna basmamalı, yalnızca BOŞLUK (Space) tuşunu kullanmalısınız. Endüstriyel standart her alt seviye için 2 boşluktur.

❌ YANLIŞ (TAB veya Eşitsiz Boşluk)
server:\n\tport: 8080    # TAB kullanıldı (HATA!)\n  host: localhost
✅ DOĞRU (2 Boşluk Standart)
server:\n  port: 8080    # 2 boşluk bırakıldı\n  host: localhost

3. Temel YAML Sözdizim Elemanları

A. İki Nokta Üst Üste Sonrası Boşluk Kuralı: Anahtar isminden sonra iki nokta koyduktan sonra mutlaka en az 1 boşluk bırakmalısınız:
port:80 ❌ HATALIDIR!  |  port: 80 ✅ DOĞRUDUR.
B. Listeler (Diziler): Liste elemanları tire (-) ve bir boşluk ile yazılır: 
roller:\n  - yonetici\n  - gelistirici\n  - test_uzmani
C. Çok Satırlı Metinler (| vs >):
| (Literal Blok - Satırları Korur): metin: |
  Satır 1 aynen kalır.
  Satır 2 alt satırda kalır.
> (Folded Blok - Birleştirir): metin: >
  Bu iki satır tek bir
  uzun cümle olarak birleşir.
⚠️ Meşhur "Norveç Tuzağı" (The Norway Problem):

YAML 1.1 spesifikasyonunda yes, no, on, off kelimeleri otomatik olarak boolean sayılır. Bir ülke listesinde Norveç'in ISO kodu olan NO yazarsanız, YAML bunu boolean false yapar! Bu nedenle bu tür değerleri daima tırnak içine almalısınız: "NO".

4. Kusursuz Bir YAML Örneği (Docker Compose) 

version: "3.8"
services:
  web_api:
    image: node:18-alpine
    container_name: backend_servisi
    restart: always
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DB_PORT=5432
FORMAT 03

XML (eXtensible Markup Language) Konu Anlatımı

Hiyerarşik, katı kurallı ve kendi veri modelini kendi etiketleriyle tanımlayan standart

1. XML Nedir ve Nerelerde Kullanılır?

XML, 1996 yılında W3C tarafından standartlaştırılmış etiket tabanlı (markup) bir meta dildir. HTML verinin nasıl görüneceğini tanımlarken (örneğin <b>kalın</b>), XML verinin ne olduğunu tanımlar (örneğin <fiyat>150</fiyat>).

📻 RSS ve Podcast: İnternetteki blog ve haber yayınları ile Spotify/Apple podcast akışları XML (RSS 2.0) kullanır.
📱 Android Uygulamaları: Android uygulama arayüzleri ve manifestoları (AndroidManifest.xml) XML tabanlıdır.
🏦 Kurumsal & Finans: Bankacılık SOAP servisleri ve e-Fatura standartları çok katı veri doğrulaması için XML kullanır.

2. XML'in 3 Katı Sözdizim Kuralı

1. Tek Kök Eleman (Single Root): Bir XML belgesinde en dışta MUTLAKA ve SADECE tek bir ana etiket olmalıdır. Yan yana iki ayrı ana kök etiket bulunamaz!
2. Eksiksiz Kapanış: Açılan her etiket mutlaka kapatılmalıdır: <etiket>...</etiket> veya kendi kendine kapanan <etiket/>.
3. Büyük/Küçük Harf Duyarlılığı: <Kitap> ile </kitap> eşleşmez! Açılış ve kapanış harfleri birebir aynı olmalıdır.

3. Nitelik (Attribute) vs Eleman ve CDATA Blokları

A. Nitelik (Attribute) vs Eleman (Element) Ayrımı:

Genel kabul görmüş kural: Verinin kimliği ve meta bilgileri nitelikte, taşınan asıl veri ise eleman etiketlerinde saklanır:

<kitap id="49" kategori="Roman">   <!-- id ve kategori niteliktir (attribute) -->
  <baslik>Nutuk</baslik>            <!-- baslik bir elemandır (element) -->
  <yazar>Mustafa Kemal Atatürk</yazar>
</kitap>
B. CDATA (Character Data) Bloğu ile Ham Kod Saklama:

XML içinde <, > veya & karakterleri bulunursa ayrıştırıcı bunları yeni etiket sanıp çöker. Kod veya ham metin saklamak için <![CDATA[ ... ]]> kullanılır: 

<script>
  <![CDATA[
    if (kullaniciPuan < 50 && seviye > 1) {
      alert("Hata yok, CDATA koruyor!");
    }
  ]]>
</script>

4. Kusursuz Bir XML Örneği (RSS Akışı) 

<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>Yazılım Bülteni</title>
    <link>https://example.com</link>
    <item>
      <title>JSON vs YAML vs XML Karşılaştırması</title>
      <author>yazar@example.com</author>
      <pubDate>Sun, 11 Oct 2026</pubDate>
    </item>
  </channel>
</rss>

JSON Kritik Kuralları

  • 1. Çift Tırnak Şartı: Tüm anahtar isimleri ("key") ve metin değerler çift tırnaklı olmalıdır. Tek tırnak geçersizdir.
  • 2. Sonda Virgül Yasak: Son elemandan sonra virgül bırakmak (trailing comma) ayrıştırıcıyı patlatır: {"a": 1,} HATALIDIR.
  • 3. Yorum Yapılamaz: JSON saf veri taşımak içindir; // veya /* */ koyamazsınız.
  • 4. Desteklenmeyenler: undefined, fonksiyonlar veya NaN bulunamaz. Boş değer için null kullanılır.

YAML Kritik Kuralları

  • 1. TAB Tuşu Yasaktır: Girintileme için daima boşluk (space) tuşu kullanın. Genelde 2 boşluk standarttır.
  • 2. İki Nokta Boşluğu: Anahtar sonrasındaki iki noktadan sonra mutlaka bir boşluk olmalıdır: port: 80 (port:80 yanlıştır).
  • 3. Norveç Tuzağı (NO): Tırnaksız NO yazarsanız, YAML 1.1 bunu boolean false yapar! Tırnak kullanın: "NO".
  • 4. DRY Miras Alma: Tekrarlanan yapıları &anchor ile işaretleyip <<: *anchor ile kopyalayabilirsiniz.

XML Kritik Kuralları

  • 1. Tek Kök (Root) Eleman: Tüm XML dökümanı mutlaka en dışta tek bir ana kapsayıcı etikete sahip olmalıdır.
  • 2. Eksiksiz Kapanış: Her etiket kapanmalıdır: <item>...</item> ya da kendi kendine kapanan <br/>.
  • 3. Büyük/Küçük Harf Duyarlılığı: <Title> ile </title> eşleşmez; etiket isimleri birebir aynı olmalıdır.
  • 4. CDATA Bloğu: İçerisinde <, >, & sembolleri olan metinler için <![CDATA[ ... ]]> kullanılır.
